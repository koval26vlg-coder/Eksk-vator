# Ekskavator — как ведём проект

Работаем в основном в **бумажном режиме** (`ARBITRAGE_PAPER=true`): live и ключи API — только осознанно, после проверки логики и лимитов; секреты только в `secrets.env`, в git не коммитим. Стек: **Python 3**, **CCXT / CCXT Pro**, asyncio, режимы **rest** и **ws** для стакана; конфигурация через **`.env`** (шаблон — `.env.example`). Изменения в коде — **точечные**, по задаче: без массовых рефакторингов и без правок в чужих файлах «заодно». Не трогаем без запроса: **секреты** в `secrets.env`, лишние markdown-файлы и документацию, не относящуюся к задаче. Для торговых рисков при скальпинге с авто-сделками учитывать **`RISK_*`** и при необходимости **`RISK_STRICT_RISK_LIMITS`** (см. комментарии в `.env.example`).

**Переменные окружения:** при добавлении или изменении ключей конфигурации агент правит **оба** файла — **`.env.example`** и **локальный `.env`** (те же имена переменных, значения по умолчанию или закомментированные строки рядом с темой блока), чтобы не пришлось искать, куда вставить новую строку. Секреты и ключи API в `.env` не подставляем — только в `secrets.env` или закомментированные плейсхолдеры. В git по-прежнему уходит код и `.env.example`; `.env` в `.gitignore`.

**Кратко:** paper-first · Python + CCXT · `.env` · минимальный дифф · секреты локально.

## Паттерны в коде (куда смотреть)

- **Strategy** — `protocols.py` (`ScalpingStrategy`): общий контракт `on_quote` для движков скальпинга; в `ws_stream` движок типизирован так.
- **Factory** — `scalping_factory.py`: сборка движка по `SCALPING_VARIANT` (`make_scalping_engine`, `engine_by_variant`, класс `ScalpingEngineFactory`).
- **Facade** — `execution_bootstrap.py` (`build_trading_execution`): риск, капитал и `OrderExecutor` собираются в одном месте.
- **Composite** — `scalping.py` (`ScalpingRotate`): несколько под-стратегий под одним `on_quote`, переключение по таймеру.
- **Repository / Gateway** — `protocols.py` (`MarketDataSource`, `ArbitrageScannerProtocol`): контракты доступа к котировкам и сканированию; реализация — `scanner.py`.
- **TA-обновление свечей** — `protocols.py` (`SupportsOhlcvRefresh`): опциональный `refresh_ohlcv` у TA-движков без общего базового класса.

## Совместная работа с ИИ

### 1. Одна задача за раз

Одна цель на итерацию или **явный порядок**: «сначала А, потом Б». Так меньше половинчатых правок и откатов.

### 2. История: что пробовали и что не сработало

Чтобы по истории было видно ход работы и **не повторять** одни и те же шаги:

- Фиксируйте изменения **осмысленными коммитами** (коротко: *что* и *зачем*).
- Если подход отвергнут или откатили — в сообщении коммита или в описании PR укажите **почему** (одна строка достаточно).

Секреты в историю не кладём. Коммитим код и `.env.example`; локальный `.env` не в репозитории, но его содержимое (без секретов) синхронизируем с шаблоном при правках конфигурации.

### 3. Минимальный тест-кейс

Перед правкой или для проверки результата формулируйте явно:

**вход** → **ожидаемый лог или число** (одна строка-пример).

Пример: «запуск с `BOT_STRATEGY=scalping`, `AUTO_TRADE=true` → в логе строка `открытых≤10` и нет `Риск: отказ… open=5/5`».

### 4. Уровень объяснений

По умолчанию — **ясно для новичка**: что сделано, где в коде, зачем; без лишнего жаргона. Если нужен только дифф без текста — напишите отдельно.

### 5. Контекст между сессиями (агент + вы)

Чтобы не повторять отклонённые шаги и помнить, что уже сделано:

| Источник | Зачем |
|----------|--------|
| **`git log --oneline -20`** | Недавние коммиты и формулировки «что/зачем». |
| **`logs/run-*.log`** | Полный вывод последних запусков `python main.py` (UTF-8). Каталог рядом с `main.py`, в git не коммитится. Точный путь к файлу текущей сессии — в первой строке `INFO arbitrage` после старта. |
| **`python scripts/context_snapshot.py`** | Один блок текста: коммиты + список свежих логов с путями — вставить в начало сообщения агенту. |
| **Правило `.cursor/rules/eksavator-collaboration.mdc`** | Просит агента при новой порции работы опираться на git и `logs/`. |
| **Транскрипты Cursor** | Длинная история чатов по проекту в папке agent-transcripts профиля; для точечного восстановления — поиск по словам (имя фичи, ошибка). |

Имеет смысл по-прежнему **осмысленные коммиты** и при откате — одна строка «почему» в сообщении.
